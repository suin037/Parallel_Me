iframe 임베드 테스트

전시관 뷰페이지가 우리 사이트를 프레임으로 감쌌을 때를 흉내낸다. 아이폰·아이패드 사파리에서 여는 게 이 테스트의 전부다 — PC·안드로이드는 원래 되던 환경이라 여기서 구분되지 않는다.

안 뜰 때 판독법 — 무엇이 보이는지가 곧 원인이다

사이트에 진단 장치를 넣어뒀다. 이제 그냥 하얀 화면이 아니라 왜 안 뜨는지가 화면에 찍힌다. 아래 넷 중 어느 쪽인지만 알려주면 된다.

  • 빨간 제목 "화면을 띄우지 못했습니다" — 원인이 그 아래 상자에 그대로 적혀 있다. 이 화면을 캡처해서 보낼 것. 한 줄이면 고칠 수 있다.
  • "화면이 비어 있습니다"(8초쯤 뒤) — 에러 없이 아무것도 안 그려진 경우다. iOS가 메모리 부족으로 프레임을 정지시켰을 가능성이 크다.
  • 완전한 흰 화면 — 아무 글자도 없음 — 감시 장치조차 안 돌았다는 뜻이다. 먼저 프레임 새로고침을 눌러보고, 그래도 같으면 그대로 알릴 것.
  • 정상적으로 뜬다 — 고쳐진 것이다. 위 체크리스트를 계속 진행.

결과 숫자 — 이 값이 나와야 정상

PC에서 API를 직접 불러 확인해 둔 값이다. 폰 프레임 안에서도 같은 숫자가 나오면 모델·데이터·CORS가 전부 살아있다는 뜻이다.

지원은 29세라 청년패널(YP) 모델을 탄다. 그래서 후회 리스크가 5년까지만 나오는 게 정상이다(YP 관측 지평이 5년). 10년 값이 보이면 YP 모델이 안 붙은 것이다. 도현·성민은 10년까지 나온다.

  • 소수점 아래는 화면 반올림에 따라 다를 수 있다. 부호와 자릿수만 맞으면 된다.
  • 세 명 모두 0 이거나 값이 비어 있으면 → 백엔드 연결 실패다.

안 떠도 정상인 것

  • Claude 해설이 빠지고 배너만 뜨는 경우 — 하루 한도(2000회)를 넘겼을 때의 의도된 동작이다. 숫자·그래프는 그대로 나온다. 오늘 사용량은 0이라 지금은 안 뜬다.
  • 결과 화면 장면 이미지 — 이미지 생성 키가 아직 안 붙어 있다.
  • 진학(enroll) 선택지의 인과효과 — 학습 표본이 부족해 의도적으로 안 돌린다.

왜 4번이 핵심인가

  • 이 앱은 상태를 전부 브라우저 저장소에 넣는다. 크로스 오리진 iframe 안에서는 사파리·iOS가 그걸 막는다 (크롬·파이어폭스는 파티션 저장소로 그럭저럭 동작).
  • 막힌 채로 두면 카드를 눌러도 슬롯이 안 써지고 빈 우주가 뜬다 — 에러도 안 나서 원인을 못 찾는다.
  • 그래서 저장소를 safeStorage.js 로 감싸 막히면 메모리로 대신하게 했고, 세션을 날리던 전체 새로고침도 걷어냈다.
  • iOS는 크롬을 써도 엔진이 WebKit이라 사파리와 같다. 아이폰 하나면 검증이 끝난다.

폰에서 여는 법

  • 이 파일을 카톡·메일로 자기 폰에 보내 열거나,
  • PC에서 이 폴더에 대고 python -m http.server 8080 을 띄우고 폰으로 http://<PC IP>:8080/iframe-test.html 접속.
  • 둘 다 같은 파일이라 결과는 같다. 카톡 쪽이 빠르다.

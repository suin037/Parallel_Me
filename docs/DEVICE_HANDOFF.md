# 기기 옮기기 — 링크 하나로 폰↔노트북 이어서 하기

- **작성일**: 2026-08-16
- **한 줄**: 체험 기록을 링크의 `#` 뒤에 실어 다른 기기로 옮긴다. **서버·계정·DB 없음.**

전시 관람객이 폰으로 QR을 찍어 체험하다가 노트북으로 옮기거나, 부스 노트북에서 보던 걸
자기 폰으로 가져가는 용도. 로그인을 만들지 않고 이것만으로 해결한다.

---

## 1. 왜 이렇게 만들었나

처음엔 Auth0 로그인, 그다음엔 서버에 7일 보관하는 방식을 검토했다가 둘 다 접었다.

| 검토안 | 접은 이유 |
|---|---|
| Auth0 로그인 | Universal Login이 `X-Frame-Options`로 **iframe에서 렌더 자체가 안 됨**. 온라인 전시관은 iframe 임베드가 제출 조건이라 로그인 시점에 흰 화면이 된다. 서드파티 쿠키 차단으로 세션 유지도 깨진다. |
| 서버 7일 보관 | Render free 플랜은 **디스크가 ephemeral**이고 15분 유휴 시 인스턴스가 내려간다. 메모리 dict도 SQLite 파일도 살아남지 못해 외부 KV 스토어가 추가로 필요했다. |
| **링크 전달 (채택)** | 요구가 '보관'이 아니라 '옮기기'였다. 서버가 없으니 콜드스타트·다운·트래픽 걱정도 함께 사라진다. |

부수 효과로 **출품 요강의 "트래픽 초과 시 체험 중단" 리스크에서 이 기능만큼은 자유롭다.**

### `#` 뒤에 싣는 이유

fragment는 브라우저가 서버로 **전송하지 않는다.** Vercel 접속 로그에도, 우리 백엔드에도
기록이 남지 않는다. 쿼리스트링(`?d=`)으로 하면 그대로 로그에 찍힌다.

## 2. 사용 흐름

**폰 → 노트북** (주 용도)
> 설정 → 프로필 → "다른 기기에서 이어서 하기" → **공유하기**(카톡 나에게 보내기·메일) 또는
> **링크 복사** → 노트북에서 그 링크를 열면 `/resume`이 뜬다 → "이 기기로 불러오기"

노트북엔 카메라가 마땅치 않아 QR 대신 링크를 쓴다.

**노트북 → 폰** (덤)
> 같은 화면의 **QR**을 폰 카메라로 찍는다. 단, 데이터가 크면 QR은 안 뜬다 (§5 참고).

## 3. 파일 구성

| 파일 | 역할 |
|---|---|
| `frontend/src/data/handoff.js` | 상태 수집·gzip·base64url·링크 생성/파싱. UI 없음 |
| `frontend/src/screens/Handoff.jsx` | `/handoff` — 보내는 쪽 (요약·공유·복사·QR) |
| `frontend/src/screens/Resume.jsx` | `/resume` — 받는 쪽 (미리보기·덮어쓰기 경고·불러오기) |

**옮기는 것**: `localStorage`의 `pm.*` 키 전부 — 프로필·아바타·체크인·일기·시나리오·펫·설정

**옮기지 않는 것** (`handoff.js`의 `SKIP`)

| 키 | 제외 이유 |
|---|---|
| `pm.sec.salt.v1` · `pm.sec.verify.v1` | 그 기기에서만 의미 있는 암호 재료. 옮기면 오히려 잠금이 꼬인다 |
| `pm.anonId.v1` | 기기별 익명 식별자. 복사되면 한 사람이 두 명으로 집계된다 |
| `pm.chatDraft.v1` | 쓰다 만 초안 |
| `pm.guide.seen.v1` | 새 기기에선 가이드를 한 번 보는 게 맞다 |

받을 때도 `pm.` 네임스페이스 밖은 **쓰지 않는다.** 조작된 링크로 다른 키를 심는 걸 막기 위한 것.

## 4. 배포해야 완전히 동작한다

기능 자체는 로컬에서도 되지만, **공유·복사 버튼은 HTTPS(보안 컨텍스트)에서만 작동한다.**

| 환경 | 공유하기 | 링크 복사 | QR | 비고 |
|---|---|---|---|---|
| `localhost:5173` | ❌ (폰 아님) | ✅ | ✅ | localhost는 보안 컨텍스트로 인정됨 |
| `http://192.168.x.x` (LAN 테스트) | ❌ | ❌ | ✅ | **평문 HTTP라 두 API 모두 차단.** 화면 하단 링크 상자에서 직접 복사해야 함 |
| 배포 (HTTPS) | ✅ | ✅ | ✅ | 정상 |

폰 실기기 테스트를 LAN IP로 하면 버튼이 안 먹는 게 **정상**이다. 버그로 오해하지 말 것.

### 배포 전 확인

- [ ] `vercel.json`의 SPA rewrite가 살아 있을 것 — 없으면 `/resume` 직접 진입이 404가 난다

```json
"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
```

- [ ] 도메인 설정은 **불필요**. `buildResumeLink()`가 `window.location.origin`을 쓰므로
      새 도메인으로 옮겨도 자동으로 따라간다

## 5. 새 저장소로 옮길 때 빠뜨리기 쉬운 것

기능이 파일 3개로 끝나지 않고 기존 파일 4곳을 건드린다. 정리하면서 누락되기 쉬우니 확인할 것.

| 파일 | 넣어야 할 것 |
|---|---|
| `frontend/package.json` | **`qrcode` 의존성** (QR 생성. 이것만 별도 설치가 필요하다) |
| `frontend/src/App.jsx` | `import Handoff/Resume` + 라우트 `/handoff` · `/resume` 2개 |
| `frontend/src/components/Layout.jsx` | `NO_TABBAR` · `NO_PROFILE` · `showBack` 배열에 `/resume` |
| `frontend/src/screens/Settings.jsx` | 프로필 섹션의 "다른 기기에서 이어서 하기" 카드 + `Smartphone` 아이콘 import |

`/resume`을 탭바에서 빼는 이유: 링크로 처음 들어오는 자리라 아직 이 기기엔 기록이 없다.
탭으로 다른 화면에 가봐야 빈 화면만 보이므로 불러오기 결정에만 집중시킨다.

## 6. 제약과 알아둘 점

### QR은 데이터가 작을 때만 뜬다

QR 바이트 모드의 물리적 최대 용량이 **2,953바이트**다. 실측 결과:

```
1년치 시드 데이터  원본 88.7KB → gzip 후 링크 3.0KB  → QR 불가 (링크 공유로 자동 폴백)
페르소나 · 짧은 체험                        ~1KB 이하  → QR 정상
```

`handoff.js`의 `QR_MAX = 1200`을 넘으면 QR 자리에 "링크 공유·복사를 사용하세요" 안내가 뜬다.
**폰 → 노트북(주 용도)은 링크 방식이라 영향 없다.** 오프라인 전시에서 QR을 크게 쓸 계획이면
이 제약을 감안할 것.

### 링크 자체가 열쇠다

받은 사람은 누구든 그 기록을 본다. 화면에 명시해 두었지만 운영 시에도 인지 필요.

### 메신저에는 남는다

`#` 뒤가 우리 서버에 안 남는 것과, 카톡으로 보낸 링크가 카톡에 남는 것은 별개다.
화면 안내에 "옮긴 뒤 대화를 지워주세요"를 포함했다.

### 덮어쓰기

`/resume`에서 불러오면 겹치는 키는 덮어쓴다. 되돌릴 수 없어서, 받는 기기에 이미 기록이 있으면
경고를 띄우고 한 번 확인을 받는다 (공용 노트북에서 남의 기록을 날리는 사고 방지).

### 구형 브라우저

`CompressionStream`이 없으면(Safari 16.4 미만) 무압축으로 자동 폴백한다. 링크가 길어질 뿐
동작은 같다. payload 첫 글자가 `z`(압축) / `r`(원본) 구분자다.

## 7. 검증 상태

왕복 테스트 통과 — 한글·이모지, 1년치 규모, 청크 경계(60KB), 손상된 링크 throw. 빌드 통과.

**브라우저 실구동 테스트는 하지 않았다.** 배포 후 아래를 눈으로 확인할 것:

1. 설정 → 프로필 → "옮기기" → 링크 복사
2. 다른 브라우저(시크릿 창)에 붙여넣기 → 요약이 뜨는지
3. "이 기기로 불러오기" → `/my`에서 기록이 그대로인지
4. 폰 실기기로 QR 스캔 (배포 HTTPS 환경에서)

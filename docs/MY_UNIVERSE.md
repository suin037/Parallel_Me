# 나의 우주 (별자리) — 구현 공유

담당: 민주 · 브랜치 `minju/my-universe` · 2026-08-02
기준 커밋: `df796d1` (통합본) · `vite build` 통과

일기·체크인 기록이 하루에 별 하나씩 쌓여 **일주일마다 별자리 하나**가 되는 화면입니다.
새 라이브러리 없이 localStorage + 순수함수로만 만들었습니다.

## 지금 바로 확인하는 법

```
npm --prefix frontend run dev
http://localhost:5173/my?demo=1   ← 3주치 예시가 자동으로 채워짐
http://localhost:5173/my          ← 빈 상태 → "✦ 예시 기록으로 둘러보기"
```

`?demo=1`은 발표·심사용 링크입니다. 기존 기록이 있으면 건드리지 않습니다.
예시가 들어있는 동안은 화면 상단에 **"예시 데이터로 둘러보는 중 — 내 기록이 아닙니다"** 배지와 '비우기' 버튼이 항상 떠 있습니다. 심사위원에게 남의 기록을 본인 것처럼 보여주지 않기 위한 장치라 지우지 말아주세요.

## 다른 파트에서 붙이는 법 — 함수 하나입니다

일기 / 데일리체크인 화면에서 저장이 끝나면 이 함수만 부르면 별이 생깁니다.

```js
import { addCheckin } from "../data/myUniverse.js";

addCheckin({
  date:    "2026-08-02",  // 생략 시 오늘
  mood:    4,             // 이모지 1~5  → 내부에서 valence로 변환
  valence: 0.5,           // -1~1 을 직접 줄 수 있으면 이쪽 우선
  energy:  3,             // 소현님 체크인 3문항
  skill:   "협업",        //
  keyword: "뿌듯",        //
  note:    "한 줄 기록",
  diaryId: "d_123",       // 일기 본문 식별자(있으면)
});
```

- **같은 날짜로 다시 부르면 그날 별을 덮어씁니다**(upsert). 중복 별이 생기지 않으니 저장할 때마다 자유롭게 호출하세요.
- `valence`를 주면 그대로 쓰고, `mood`만 주면 `moodToValence`가 −1~1로 변환합니다. **일기 감정분석이 붙으면 `valence`로 넘겨주시는 게 정확합니다.**
- `note`나 `diaryId`가 있으면 `hasDiary: true`가 되어 XP가 10 → 25로 올라갑니다.

호출만 하면 별·별자리·XP·홈 통계가 전부 자동으로 갱신됩니다. 다른 배선은 필요 없습니다.

> 현재 `addCheckin`을 부르는 곳이 프로젝트에 없습니다. 일기·데일리체크인 화면이 아직 없어서, 지금은 데모 시드로만 별이 채워집니다.

## 규칙 (왜 이렇게 정했는지)

**별 1개 = 하루 1개. 별자리 1개 = 별 7개(달력 한 주, 월~일).**

7로 정한 이유는 셋입니다. ① 주간 리포트와 주기가 정확히 같아 그대로 재사용 가능 ② 슬롯이 항상 7칸이라 진행 중에도 레이아웃이 안 흔들림 ③ 12개(황도12궁)면 신규 사용자가 첫 별자리를 12일 뒤에나 봅니다.

**이름 = `{모양}형 {주제} 별자리`** (예: "도전형 성장 별자리")

모양은 그 주 valence 7개의 평균과 표준편차로 정합니다:

| | 진폭 작음 (sd < 0.35) | 진폭 큼 (sd ≥ 0.35) |
|---|---|---|
| 평균 ≥ 0.15 | 순항 | **도전** |
| 중간 | 균형 | 기복 |
| 평균 ≤ −0.15 | 인내 | 격동 |

주제는 `profile.value_ranking` 1순위 카드의 axis(경제/관계/성장/자기실현/안정)를 씁니다.

**기록이 7일 중 4일 미만이면 이름을 붙이지 않고 "흐린 별자리"로 둡니다.** 2~3일 기록으로 한 주를 규정하면 과잉 해석이라서요. (`MIN_RECORDS_TO_NAME = 4`)

임계값 3개(`THRESHOLDS`)는 초안입니다. 실사용 로그가 쌓이면 조정 대상이에요.

**감정은 색이 아니라 별의 밝기·크기로 표현했습니다.** 시안/골드는 앱 전체에서 A/B 전용 색이라 감정에 쓰면 의미가 충돌합니다. 디자인 문서의 "글로우·네온 남발 금지" 원칙과도 맞습니다.

## 저장

```
localStorage["pm.myuniverse.v1"]
  { checkins[], pinnedSlots{A,B,C}, planet, simRuns, demo }
```

- `savedUniverses.js` / `prefs.js` 와 같은 패턴입니다.
- **XP는 저장하지 않고 활동 기록에서 매번 파생합니다** — 중복 적립·불일치를 막기 위해서요. (`checkin 10 / diary 15 / simulation 50 / universeSaved 30 / reflection 40`)
- `pinnedSlots`는 보관함 우주의 **id 포인터**만 들고 데이터를 복사하지 않습니다.
- 나중에 Supabase로 옮길 때는 `myUniverse.js`의 `loadUniverse` / `persist` **두 함수만** 바꾸면 됩니다. 저장 접근을 전부 여기 모아뒀습니다.

localStorage는 브라우저 하나에 묶입니다. 계정·기기 간 동기화가 필요해지는 시점이 Supabase 전환 시점이에요.

## 홈 화면이 바뀐 부분

`HomeHub.jsx`의 시뮬레이션·수집한 별·탐험한 우주 카운트가 **하드코딩 상수에서 실제 저장소 파생으로 교체**됐습니다(`universeSummary()`). 세 숫자가 나의 우주와 항상 일치합니다.

## ⚠️ 안전 이슈 — 일기 화면 만드실 분께

백엔드에 일기 감정분석(`diary_bridge.analyze_diary`)과 위기 감지가 이미 있는데, **`/simulate` 안에서만 호출됩니다.** HTTP로 노출된 엔드포인트가 없어요.

그래서 지금 구조대로면 **매일 쓰는 일기에는 위기 감지가 걸리지 않고**, 시뮬레이션을 돌려야만 상담 안내(109 · 1577-0199 · 1388)가 뜹니다. 일기 입력 경로를 만들 때 이 부분을 반드시 함께 태워주세요.

다만 **엔드포인트를 만들기 전에 정본을 먼저 확정해야 합니다.** 위기 감지 구현이 두 벌 있습니다:

| 구현 | 위치 | 형태 |
|---|---|---|
| `assess_safety` | `backend/rag/safety.py` | 감정 + 텍스트, `crisis` 레벨 |
| `detect` / `support_message` | `diary_module/crisis.py` | LEVEL 1~3, 관용구·창작물 오탐 억제 포함 |

어느 쪽을 쓸지 정하지 않은 채 엔드포인트를 만들면 계약이 굳어버려 나중에 되돌려야 합니다. 정본 확정 → 엔드포인트 순서로 가면 좋겠습니다.

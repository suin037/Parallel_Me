# 결정 기록 — 삶의질 지표 집계: 합산(sum) → 평균(mean) (2026-07-30)

담당: 수인 (예측 엔진 / personalize.py) · 관련: 지윤(value_ranking 매핑), 소현(프론트)

## 배경

성향 개인화(Option A)는 사용자 가치 **5축**(경제·관계·성장·자기실현·안정)을 엔진 **3지표**(경제적안정도·성장가능성·삶의질)로 변환해 "어느 지표·서사를 앞세울지"를 정한다. 매핑은 지윤 `qmode/value_ranking.py`의 `AXIS_TO_INDICATOR`:

| 가치 축 | 엔진 지표 |
|---|---|
| 경제 | 경제적안정도 |
| 성장 | 성장가능성 |
| 관계 · 자기실현 · 안정 | **삶의질** (3축 → 1지표) |

## 문제

`personalize.indicator_weights()`가 지표 가중치를 **합산(sum)**으로 계산했다.
→ 삶의질은 3개 축을 다 더하므로 **구조적으로 과대대표**된다.

실측(성장을 1순위로 정렬한 온보딩 → `axis_weights`):
- value_weights = `{성장 0.32, 안정 0.24, 경제 0.16, 관계 0.14, 자기실현 0.14}`
- 합산: 삶의질 = 0.14+0.14+0.24 = **0.52** > 성장 0.32
- 결과: `narrate_order`·`focus`가 **삶의질** 선두 → "성장이 1순위라고 했는데 왜 삶의질을 앞세워?" 하는 어색함.

## 결정

**집계를 평균(mean)으로 변경한다.** 각 지표 가중치 = 그 지표로 매핑되는 축들의 **평균**.
- 경제적안정도 = mean(경제), 성장가능성 = mean(성장)
- 삶의질 = mean(관계, 자기실현, 안정) — 3축을 흡수하되 평균이라 과대대표 안 됨
- 세 지표 합이 1이 되도록 정규화.

같은 실측 재계산(평균):
- 삶의질 = mean(0.14,0.14,0.24) ≈ 0.173 → 정규화 후 성장가능성이 **선두**. ✅

## 근거

- 개인화의 목적은 "사용자가 **중요하다고 꼽은** 축을 앞세우는 것". 합산은 축 개수(3 vs 1)에 좌우돼 실제 우선순위를 왜곡한다. 평균은 지표별 **평균 중요도**라 사용자의 선택을 더 정직하게 반영한다.
- 제품 원칙(권유/단정 회피)과도 무관하게 안전한 변경(강조 순서만 조정).

## 범위 / 원칙 준수

- **지윤 `AXIS_TO_INDICATOR` 매핑은 손대지 않음.** 변경은 우리 쪽 집계(`personalize.indicator_weights`) 한 곳뿐.
- 코드에 변경 표시 + **이전 sum 코드는 주석으로 보존**(되돌리기 가능).
- 회귀 테스트 추가: 성장 1순위 → `narrate_order[0] == 성장가능성` (합산이면 실패).

## 남은 확인

- 지윤에게 "집계를 mean으로 바꿨다" 통지(매핑은 그대로). 관계·자기실현·안정을 삶의질 하나로 접는 매핑 자체를 더 세분화(예: 관계 별도 지표)할지는 별도 논의.
- 코드 위치: `backend/personalize.py :: indicator_weights()`. 문서: 본 파일 + 프로젝트 `claude/개인화_진행상태_2026-07-30.md`.

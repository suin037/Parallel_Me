# Parallel Me

> 고민 중인 두 갈림길을, 실제 패널 데이터에서 **같은 선택을 한 사람들이 실제로 어떻게 됐는지**로 비교한다.

삶은계란 팀 · 2026

---

## 왜 만들었나

GOMS 집계로 이직자의 소득 변화를 보면 이렇게 나온다.

```
보건의료 +30.4%   경영사무 +29.3%   연구공학 +28.5%   …   미용여행 +2.0%
```

"이직하면 30% 오른다"고 말하고 싶어진다. 그런데 같은 데이터에 인과추론(Double ML)을 걸면 **이직의 순효과는 1년차 +5.8만원**이다. 30%가 아니라 2% 남짓.

차이는 **누가 이직하는가**에서 온다. 옮길 수 있는 사람은 원래 옮길 만한 조건을 갖고 있다. 단순 비교는 그 조건까지 이직의 효과로 계산한다.

이 프로젝트는 그 간극을 화면에 올린다. 숫자를 크게 보여주는 게 아니라, **그 숫자가 무엇을 재고 무엇을 못 재는지** 같이 보여주는 쪽을 골랐다.

## 하는 것과 하지 않는 것

| 한다 | 하지 않는다 |
|---|---|
| 같은 조건에서 그 선택을 한 사람들의 1·3·5년 관측 경로 | 당신의 미래값 예측 |
| 인과추론으로 뽑은 선택의 순효과 + 95% 신뢰구간 | 점추정 하나만 크게 띄우기 |
| 근거가 없는 지표는 비우고 이유를 적기 | 빈칸을 중립값으로 채우기 |
| 사용자가 적은 조건(연봉·창업비·공백)을 수치에 반영 | 그 값을 모델이 낸 것처럼 보이게 하기 |

마지막 줄이 이 저장소에서 가장 자주 등장하는 규칙이다. `PrivacyVault.jsx` 상단에도 같은 말이 적혀 있다 — **하지 않는 일을 한다고 적지 않는다.**

## 데이터와 모델

5개 레이어를 쌓았다. 새 모델을 만들기보다 **공개 패널에서 답할 수 있는 것만** 골랐다.

| 레이어 | 데이터 | 하는 일 |
|---|---|---|
| L1 룰베이스 | GOMS 11,318명 | 직종별 집계 — 위에서 말한 "+28.5%" 쪽 |
| L2 KNN | GOMS | 유사 사례 매칭 (임금 MAE 18.0만원, 중앙값 기준선 대비 68.7% 개선) |
| L3 인과 | KLIPS 12–27차 | Double ML — 선택의 순효과와 신뢰구간 |
| L4 생존 | KLIPS 스펠 | 이탈·복귀까지 걸리는 기간 |
| L5 궤적 | KLIPS·YP | 연차별 소득·만족도 분포 |

처치별 표본은 이만큼이다.

| 선택 | 처치군 | 학습 | 1년차 효과 |
|---|---|---|---|
| 이직 | 5,498 | O | +5.8만원 |
| 창업 | 703 | O | +47.2만원 |
| 쉬어가기 | 1,344 | O | +18.0만원 |
| 진학 | 178 | **X** | — |

진학은 학습하지 않았다. 처치군 178건은 최소 기준 200건에 못 미친다. 신뢰구간이 너무 넓어 어떤 말도 할 수 없어서, 모델을 만드는 대신 **없다고 적었다.**

## 아는 것보다 모르는 것을 적는 게 어렵다

숫자를 내놓은 뒤에도 남는 문제들이 있다. 감추지 않고 화면과 문서에 적어 두었다.

**쉬어가기 — 5개 연차 중 4개가 0과 구별되지 않는다.**
1년 +18.0만원만 유의하고 2·3·4·5년은 신뢰구간이 0을 포함한다. 게다가 결과변수가 `t+h` 시점의 월임금이라 **공백 기간의 0원이 애초에 안 들어 있다.** 그래서 "반년 쉬었는데 소득이 더 높다"는 화면이 나온다. 재학습 전까지는 월소득을 그대로 두고, 공백을 반영한 **누적 소득**을 따로 보여준다.

**창업 +47만원은 임금과 사업소득을 비교한 값이다.**
임금근로자는 월평균임금(`p{w}1642`), 자영은 월평균 사업소득(`p{w}1672`)이다. 개념이 다르다. 게다가 폐업해 소득이 끊긴 사람은 결과 관측에서 빠져 생존편의가 남는다. "창업하면 47만원 더 번다"가 아니라 **"창업으로 전환해 살아남은 사람의 신고 소득이 임금 대비 이만큼 높게 관측된다"** 로 읽어야 한다.

**해외 취업은 답하지 못한다.**
패널이 전부 국내 자료다. 런던에서 일하는 경로를 잰 기록이 없다. 분류기가 "런던에 남아 현지 취업"을 '현직 유지'로 보고 국내 잔류자 궤적을 그린 적이 있어서, 지금은 감지해서 **비우고 이유를 적는다.**

**생존모델 C-index는 0.58이다.**
0.5가 무작위다. 개인 예측으로 쓰기엔 약하다. 그래서 재직기간은 '참고'로만 두고 비교의 근거로 삼지 않는다.

검증 과정은 `docs/JOB_CHANGE_MODEL_VALIDATION.md`·`docs/JOB_CHANGE_MODEL_TEMPORAL_VALIDATION.md`에, 그날그날 판단은 `WORKLOG.md`에 남아 있다.

## 화면

17개 라우트, API 40개(예측 10 + 일기·LLM 30).

- **시뮬레이션** — 두 갈림길 입력 → A/B 비교. 조건(연봉 변화·창업비·공백 기간)을 적으면 수치에 반영되고, 반영된 값은 "모델 예측이 아니라 입력"이라고 표시된다
- **체험하기** — 1년치 기록을 가진 가상 인물 7명. 로그인 없이 남의 자리에서 바로 볼 수 있다
- **나의 우주** — 기록이 별이 되고 별이 모여 별자리가 된다. 3D
- **일기·체크인** — 30초 체크인과 질문형 일기. 감정 신호는 서사와 안전 분기에만 쓰고 **예측 수치는 바꾸지 않는다**

## 저장소 구조

```text
backend/          예측 API — 레이어 L1~L5, 비교 로직, 심리 RAG
diary_module/     일기·체크인·챗봇 (qmode)
frontend/         React 화면
data/             가공 데이터 (개인 단위 원자료는 커밋하지 않는다)
docs/             API·데이터 감사·모델 검증·기능 명세
preprocess/       데이터셋별 전처리
tests/            통합·검증 테스트
```

루트의 `build_*`·`train_*`·`evaluate_*`·`validate_*`는 모델 파이프라인 재현용이다. 서비스를 띄우는 데는 필요 없다.

## 로컬 실행

### 환경 변수

```powershell
Copy-Item .env.example .env
```

키가 없어도 통계 기능은 돈다. AI 서사와 이미지 생성만 막힌다.

### 백엔드

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
cd backend
python -m uvicorn main:app --reload --reload-dir . --reload-dir ..\diary_module
```

기동 후 모델·패널을 올리는 데 20초쯤 걸린다. <http://127.0.0.1:8000/health> 에서 `warmup.done`과 `artifacts.available`이 `true`면 정상이다.

> `--reload-dir`를 두 개 준 이유: `--reload`는 현재 폴더만 감시한다. `diary_module/`을 빼면 일기·LLM 쪽을 고쳐도 서버가 다시 뜨지 않는다.

### 프론트엔드

```powershell
cd frontend
npm install
npm run dev
```

<http://127.0.0.1:5173>

`backend/models/artifacts/*.pkl`은 187MB라 저장소에 없다. `python scripts/fetch_artifacts.py`로 받는다. 없으면 서버는 뜨지만 실수치 대신 폴백이 나온다.
